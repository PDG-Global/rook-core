# Smoke run configs (2-vCPU FreeBSD 15.1 test VM, 2026-11-11 → 2026-11-14)

The server-side configs behind the published runs on the site's
Testing-and-numbers page, kept so those numbers can be reproduced. Files
come from the load-test account's home directory on the test VM, renamed
for clarity:

| File | Original name on the VM | Run |
| --- | --- | --- |
| `rookd-soak.toml` | `rookd.toml` | 24-hour stability soak, 2026-11-12 → 13 (`tools/soak.sh`) |
| `rookd-connlimit.toml` | `rookd-lifted.toml` | The connection-limit runs behind "At the connection limit" |
| `page-server.py`, `page.html` | same names | Soak HTTP upstream, 127.0.0.1:9000 |
| `ws-echo.py` | same name | Soak WebSocket echo upstream, 127.0.0.1:9001 |
| `sat-upstream.Caddyfile`, `sat-www/index.html` | `sat-upstream.Caddyfile`, `sat-www/index.html` | 1 KiB file-server upstream, 127.0.0.1:9000, behind both throughput tables and the connection-limit runs |

## What each config shows

`rookd-soak.toml` — shipped defaults, plus the `/ws` route (added 2026-11-12
for the soak) and strikes in log-only mode. The soak watches state drift at
shipped limits, so no limits are raised here.

`rookd-connlimit.toml` — per-address limits raised (1,000,000 requests per
second and burst, 100,000 per-address connections and per-address upstream
connections) so a single load generator can offer 500–12,000 connections;
`max_connections` is left at its 4,096 default and strikes are log-only,
exactly as the numbers page describes.

`page-server.py` reads `./page.html`, so run it from this directory.

## Not in this directory

The load generator for the connection-limit runs was a 4-vCPU Google Cloud
n2-standard-4 instance that no longer exists. Its hosts entry and run
commands died with it; the numbers page records its spec (same region and
network as the 2-vCPU target, TLS to `example.com` via a hosts entry,
60-second runs, 1 KiB responses). The side-by-side bench config is
generated by `tools/bench-vs-caddy.sh`, so it is not duplicated here.
